## Context

См. `proposal.md` (зачем) и дельты в `specs/`. Сейчас `MountType` = `corner` | `downward`; эмиттер — один `Segment`; `emitAngle` крутит только `corner` у стены; схема рисует `<line class="led-strip">`. Окклюдеры — только осевые прямоугольники полок и бленды (`segmentHitsRect`).

Координаты как в `openspec/project.md`: +X в комнату, +Y вверх, мм. Карман угловых: `x = upper.depth - blend.thickness` (0 толщины бленды → кромка полки), `y = gap - profileDrop`.

## Goals / Non-Goals

**Goals:**

- Заменить один отрезок на список излучающих поверхностей (отрезки + дуга) в `src/geometry`, без расчёта в React.
- Добавить тело Г-профиля в окклюдеры; не самопересекать луч с гранью, с которой он стартовал.
- Отдать схеме полигон/путь тела (`src/viz`) и четыре монтажа в контролах/URL (`src/ui`, `src/state`).
- Обновить описание монтажа в `openspec/project.md`, чтобы SoT совпал с кодом.

**Non-Goals:**

- Хостинг, новые зависимости, фотометрия.
- Клип произвольного многоугольника сверх прямоугольника и прямоугольного треугольника в кармане.
- Менять семантику `downward` и `profileDrop`.

## Decisions

### 1. Четыре значения `mount`, без `emitAngle`

`downward` | `radius` | `ell` | `triangle`. Поле `led.emitAngle` убираем из модели. В `parseParams` `lea` игнорируется, `mount=corner` → `triangle`.

Альтернатива «оставить `corner` + угол» отвергнута: угол больше не параметр.

### 2. Карман и размер W

`W = led.width`. Тело угловых вписывается в квадрат
`[pocketX - W, pocketX] × [pocketY - W, pocketY]`.

- `triangle`: катеты W, гипотенуза от `(pocketX - W, pocketY)` до `(pocketX, pocketY - W)`, нормаль в залив `normalize(-1, -1)`.
- `ell`: тот же квадрат; светят левая грань (нормаль `(-1, 0)`) и нижняя `(0, -1)`.
- `radius`: четвертьокружность с центром в кармане, θ от π до 3π/2; нормаль в точке — радиус в залив.

`downward` по-прежнему горизонтальный отрезок от `offsetFromWall`. Валидация угловых: `W + blend.thickness <= upper.depth` (не пересечь стену).

Альтернатива «W = гипотенуза» отвергнута решением explore.

### 3. Несколько поверхностей в ядре, не в UI

`BuiltScene` хранит `emitSurfaces[]` (отрезок с нормалью или дуга) и опциональный `profileBody` (квадрат для `ell`; для `triangle`/`radius` тело в окклюзию не кладём: полуплоскость гипотенузы и радиальной дуги закрывает ход сквозь алюминий). `evaluateVisibility` обходит каждую поверхность: ≥16 внутренних точек + концы; для дуги — равномерно по углу.

Сэмпл сдвигается на малый ε вдоль нормали, чтобы старт на кромке тела не считался касанием окклюдера.

Альтернатива «аппроксимировать дугу ломаной в сцене» хуже: ломаная путается с телом на схеме. Альтернатива «считать блик в SVG» запрещена инвариантом.

### 4. Схема рисует тело, лучи из ядра

`buildDiagram` получает полигон/путь профиля из сцены. `SectionView` для `downward` оставляет полосу, для остальных — `path` (четверть круга / квадрат / треугольник). Лучи по-прежнему из `evaluation.samples`.

### 5. Контролы

Четыре радио. «Смещение от стены» только при `downward`. Угла нет. «Ширина ленты» остаётся подписью размера (W) — не плодим новое поле.

## Risks / Trade-offs

- [Сэмпл стартует на окклюдере и все лучи «закрыты»] → ε вдоль нормали; не включать излучающую грань во внутренность тела.
- [Дуга без тела-окклюдера пропустит экзотический луч вдоль хорды] → приемлемо для v1; при баге добавить сектор.
- [Старые ссылки `mount=corner`] → тихое чтение как `triangle`; сцена уедет от стены к бленде (ожидаемый BREAKING).

## Migration Plan

1. Поменять типы и тесты ядра, затем `evaluateScene`.
2. Схема и контролы.
3. URL: `corner` → `triangle`, перестать писать `lea`.
4. Откат — предыдущий коммит; сломанные закладки с `corner` начнут показывать треугольник у бленды.
